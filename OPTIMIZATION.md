# Производительность рендерера

## Назначение

Документ фиксирует архитектуру оптимизаций, условия инвалидирования кэшей и
методику измерений. Его следует обновлять при изменении горячего пути,
структуры кэша или параметров сборки.

Приоритеты проекта:

1. корректная геометрия и физика;
2. стабильное время кадра и контролируемое потребление памяти;
3. качество терминального вывода;
4. простота реализации.

Оптимизация не должна менять геометрию лучей, положение фоновых звёзд или
рисунок диска без отдельного решения об изменении визуальной модели.

## Конвейер кадра

Для каждого пикселя интегрируется нулевая геодезическая в метрике
Шварцшильда:

```text
d²x/dλ² = −(3/2) · h² · x / |x|⁵
```

Рендеринг разделён на два этапа.

### Трассировка геометрии

`trace_geo` определяет попадание луча в горизонт, пересечения с плоскостью
аккреционного диска и направление выхода к звёздному небу. Результат
сохраняется в `Geo` и используется следующими кадрами.

Ключ геометрического кэша включает:

- размер сетки лучей;
- масштаб;
- наклон камеры;
- вертикальный сдвиг.

Время анимации и азимут камеры в ключ не входят. Добавление одного из этих
параметров приведёт к полной трассировке каждого кадра и считается регрессией.

### Динамический шейдинг

`shade` пересчитывает только значения, зависящие от времени:

- фазу турбулентности диска;
- мерцание фоновых звёзд;
- положение звёздного поля относительно орбитальной камеры.

Статическая часть излучения диска вычисляется во время трассировки и хранится
в `Cross::em`. Пиксели без динамического содержимого отмечаются в компактной
маске и сохраняют значение предыдущего кадра.

## Используемые инварианты

### Независимость геодезических от времени

При неизменной камере траектории лучей одинаковы во всех кадрах. Анимация
диска и мерцание не требуют повторного интегрирования.

### Аксиальная симметрия

Метрика Шварцшильда и модель диска симметричны относительно оси `y`. При
изменении азимута:

- радиусы пересечений и доплеровские множители сохраняются;
- фаза турбулентности получает текущий угол камеры;
- направление выхода к небу поворачивается перед повторным поиском звёзд.

Поэтому орбитальное движение не инвалидирует геометрический кэш.

### Статические пиксели

Пиксель без диска и мерцающей звезды не меняется во времени при неподвижной
камере. `GeoCache::mask` позволяет пропускать его без чтения всей структуры
`Geo`.

## Предвычисленные функции

Гладкие функции, вызываемые для большого числа пикселей, заменены таблицами
или контролируемыми аппроксимациями:

| Функция | Реализация | Назначение |
|---|---|---|
| турбулентность диска | текстура 1024×512, билинейная интерполяция | исключить повторный `fbm3` |
| яркость галактической полосы | одномерная таблица | исключить `pow` и `exp` на пиксель |
| тональная кривая | таблица с индексом по `sqrt(x)` | сохранить точность около нуля |
| мерцание звёзд | полином с приведением периода | заменить системный `sin` |

Размеры таблиц и схема индексирования влияют на изображение. Их изменение
требует сравнения эталонных кадров.

## Работа с памятью

`Geo` — крупная структура, поэтому полный проход по кэшу может стать
ограничением по пропускной способности памяти. Для решений, требующих только
одного признака на пиксель, используется отдельная компактная маска.

Буферы кадра и геометрии переиспользуются. Если следующий проход полностью
перезаписывает буфер, предварительное зануление выполнять не нужно. Новую
полноразмерную копию `Geo` следует считать потенциальной регрессией.

## Терминальный вывод

ASCII- и Braille-режимы хранят предыдущее состояние экрана и отправляют
только изменившиеся диапазоны. Последовательность цвета формируется только
при фактической смене цвета, а кадр записывается одним буфером.

Пауза не запускает рендеринг до изменения состояния. Sixel использует другой
кодировщик и должен профилироваться отдельно.

## Параметры сборки

В `.cargo/config.toml` задана переносимая цель `x86-64-v2`:

```toml
[build]
rustflags = ["-C", "target-cpu=x86-64-v2"]
```

Она разрешает инструкции SSE4.1, включая аппаратные варианты `floor` и
`round`. `target-cpu=native` допустим для локального профилирования, но не для
переносимых сборок.

## Методика измерений

Измерять следует release-сборку:

```bash
cargo build --release
perf stat -e task-clock,cycles,instructions,branches,branch-misses -- \
  ./target/release/blackhole -m sixel --orbit 5
perf record -F 999 -g -- ./target/release/blackhole -m sixel --orbit 5
perf report --stdio --sort symbol
```

Для сравнения двух версий должны совпадать режим вывода, размер терминала,
число лучей, FPS, параметры камеры и длительность прогона. Первый кадр
включает трассировку и построение таблиц; установившееся время анимации нужно
измерять достаточно длинным прогоном.

Основные показатели:

- `task-clock` показывает суммарное процессорное время;
- `instructions` отражает объём выполненной работы;
- IPC (`instructions / cycles`) помогает отличить вычислительное ограничение
  от ожидания памяти;
- `branch-misses` показывает, имеет ли смысл работа с ветвлениями.

## Зафиксированный эффект оптимизаций

Исторические измерения Sixel-анимации 1500×900 при 15 FPS и орбите 5°/с:

| Состояние | Процессорное время на кадр |
|---|---:|
| полная трассировка каждого кадра | около 562 мс |
| кэш геометрии и аксиальная симметрия | около 56–84 мс |
| таблицы и оптимизации памяти | около 40 мс |

Значения получены в прежнем окружении и показывают порядок эффекта. Для
оценки текущей версии требуется повторное измерение на одной машине.

Оптимизация терминального диффа дополнительно уменьшила объём вывода примерно
с 54 до 7 КБ на кадр в тестовом ASCII-сценарии.

## Проверка корректности

Минимальный набор проверок:

```bash
cargo fmt -- --check
cargo test
cargo clippy -- -D warnings
cargo build --release
```

Для изменения рендера старый и новый бинарник должны построить одинаковые
детерминированные кадры. Проверяются как минимум:

- кадр без орбиты;
- кадр с ненулевым азимутом;
- изменение размера, масштаба и наклона;
- статические области неба и область диска;
- все три режима вывода.

Побитовое совпадение обязательно для перестройки вычислений без заявленного
изменения модели. Для намеренной аппроксимации нужно заранее определить
численную границу ошибки и визуальный критерий.

## Ограничения и отложенные направления

- Замена 64-битного хэша на 32-битный меняет расположение звёзд и рисунок
  турбулентности, поэтому не является прозрачной оптимизацией.
- Пакетная SIMD-трассировка усложняет интегратор, который после кэширования
  выполняется только при изменении геометрии.
- Увеличение таблиц без измеримой ошибки текущей интерполяции расходует память
  без подтверждённого выигрыша.

После каждой оптимизации профиль снимается заново: узкое место может перейти
из трассировки в шейдинг, терминальное кодирование или память.

## Контрольный список

1. Зафиксировать сценарий и базовые показатели `perf stat`.
2. Подтвердить горячий путь через `perf record`.
3. Выписать зависимости данных и условия инвалидирования.
4. Реализовать одно изолированное изменение.
5. Выполнить тесты и сравнить эталонные кадры.
6. Повторить измерение в тех же условиях.
7. Обновить документ при изменении архитектуры или результатов.
